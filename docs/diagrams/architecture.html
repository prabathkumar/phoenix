Layer 1 · shipped

Guided

The tester drives: click, type, pick a dropdown value, add an API check. It is also the last rung of the ladder — when the machine layers can't finish a step, a guided card asks a person: retry, scroll & retry, ask AI, give a locator, or skip.

Recording is Guided: each action is stored with a locator verified against the live page (web) or the accessibility tree (mobile); fragile locators are flagged, with keep / undo.

No model call at record time except when the tester presses “Ask AI”.

Layer 2 · shipped · proven on hardware (mobile) · real Chromium (web)

Synthetic

The generated, replayable output: a Playwright script or WebdriverIO script plus a test-case JSON both runners replay. Deterministic: recorded locators, named parameters, inferred expectations, api steps. Frozen test data replays here too.

Runs first on every replay. Never calls a model while it works. Each step reports resolvedBy: a suite that is mostly “synthetic” is healthy.

Same step list, one result contract, three platforms (android · ios · web).

Layer 3 · shipped · web + mobile · vision is opt-in

Semantic (with vision AI)

A plain-language instruction (“click Sign in”) → one element. The model is shown the element list plus a screenshot to tell look-alikes apart, and answers with a ref from the list — or declines; it never guesses.

Told what failed: the dead locator, the page diff, earlier failures. A pick that contradicts the step's expectation is retried without that element.

Web: on the shared Surface. Mobile: semantic-act.js (proven on real devices). Decides what each test-data field needs.

Layer 4 · beta · web + mobile

AI

A goal loop: look → choose one action → act → check what changed → repeat. Entry points: run-web-loop.js "goal", Ask AI in the recorder, --ai on replay.

Guards: step budget · stuck detection · never leaves the start site · stops for a person before anything irreversible (pay, delete…).

Its actions come back as proposed steps with verified locators, not just “it worked”.

▼ Falling down — when a step can't be done

Synthetic→Semantic + vision→AI→Guided

Each rung is told the failed locator, the page diff and past failures in this run. If nothing rescues the step, the failure lists every rung tried — no silent “not found”.

▲ Promoting up — the same ladder in reverse

Guided fixAI stepsSemantic locator→patch→Synthetic

Every rescue proposes a patch, gated on evidence (expectation passed, page changed, value typed); fragile locators are never promotable. Applied only by --persist / Apply — never silently. Next run passes on Synthetic alone.

Shared contract

Surface — one interface, two engines

Semantic, AI and the ladder are written once against: snapshot · screenshot · lines · perform · selectorFor.

Playwright adapter: shipped (web/surface). Appium adapter: next — needs real-device runs; hardware-proven Appium code is migrated behind tests, not rewritten blind.

Any flow · web or mobile

API step

Call an endpoint from inside a flow (e.g. DB validation): method · URL · headers · body → checks (status, JSON path, maxMs) → save values as ${NAME} for later steps. Bodies can be generated by the test data layer.

Run live in the recorder; emitted into both generated scripts; runnable alone from the API card.

Shared AI runtime — one model, every caller, no retraining needed to use it

generation/llm.js callOllamaJson(prompt, {images}) is the only place any layer talks to a model — self-hosted Ollama (pointing it at frothAI is a config change). Layers 3–4 call it; Layers 1–2 never do at replay. execution-log.js logs every call and feeds past failures back as prompt context. The test data layer calls no model: it is deterministic.

New · one AI-driven pipeline

Pipeline — scenarios to Jira, AI on every stage

engine/core/pipeline.js: scenarios → cases → test data → execution → HAR → performance → secrets → SAST → DAST → defects → AI feedback. Each stage says passed · failed · needs-you · not-built. Autonomy: ask-everything / ask-when-matters / run-everything; a live security scan and production always ask. The model reviews every stage (never sees test-data values). Jira both ways (read requirement + change requests, read defect status back; log defects without duplicates). Handlers for HAR, performance and DAST are not built here yet; Jira is not yet run against a real account.

What ties it together — honest reporting, and where the gaps are

Every layer reports honestly: “unresolved” beats a confident wrong click, across all four, on both platforms. “Succeeded” alone means no step errored — outcome-verification checks a step's declared expect against the real page diff (opt-in per step).

Not yet: web Semantic/AI proven against scripted models on real Chromium, not yet a real Ollama model on a real site · mobile ladder rungs on Appium await the Surface adapter · test data: “Create it for me” (sign-up/API to add a test user) and Excel upload are not built; not yet exercised against a real BrowserStack device or browser (web or mobile); BrowserStack Local tunnel for web and a device picker are not built.

Supporting infrastructure — confidence, pre-flight, upgrades and external access
Confidence gate + store

Locator confidence

A healed locator is promoted only with real evidence (a verified expect or a page diff) — never on “didn't throw”. locator-store.js: optional embedded SQLite, zero server.

Pre-flight + upgrades · zero cost

check-env · check-upgrades

node check-env.js verifies .env before a BrowserStack run. scripts/check-upgrades.js flags new Playwright / Appium / WebdriverIO versions — we upgrade with them (docs/UPGRADING.md).

External MCP connector

mcp/server.js

Stdio MCP server for an external client (TestOps's own MCP, Claude): locator history, test cases, execution log. run_test_case spends a real device session — gated behind confirm:true and the server's own allow flag.
